# DSECTs, USING and DROP

Scope: DSECTs defined in the program itself (`CUSTD`, `PARTD`, `PARMD`), the IBM-supplied `IHADCB` generated by `DCBD`, and `USING` and `DROP` with a register as the base, as used in DS01DSCT, DS02DSCT, QSAMPROC and BR09MTCH. Labelled and dependent `USING`, DSECTs from `COPY` members and DSECTs mapped over storage built by another program are not used in any program and are not described. Field offsets inside a DSECT with `ORG` are in the record layouts article. The programs were not assembled or run.

Source programs: DS01DSCT, DS02DSCT, QSAMPROC (`DCBD`), BR09MTCH (`DCBD`, `OPENCHK`).

## Central Idea

A DSECT is a list of names and displacements. It reserves no storage and produces no object code. It becomes useful when a register holds the address of real storage and a `USING` tells the assembler to compute every DSECT name as that register plus the displacement. The names then read whatever is at that address, whether or not it matches the layout.

## Two Parts

| Part | What it is | Example |
|---|---|---|
| Real storage | Bytes in the program: a `DC`, a `DS` buffer, a DCB, a block built by a routine | `CUSTREC DC ...`, `INAREA DS CL40`, `PARMAREA DS CL11` |
| The map | The DSECT, placed after the code | `CUSTD DSECT`, `PARTD DSECT`, `PARMD DSECT`, `IHADCB` |

The real storage has no field names. The map has no bytes. The register and `USING` join them.

## The Four Steps

```
         LA    3,CUSTREC               * 1. R3 = address of real record
         USING CUSTD,3                 * 2. Names now mean D(3)
         MVC   OUTMSG+10(8),CUSTNO     * 3. Use a field by name
         DROP  3                       * 4. End the mapping
```

- `LA` is an instruction and must run before the first use of a name.
- `USING` and `DROP` are assembler directives. They run at assembly time and generate no instruction.
- `CUSTNO` assembles as `0(3)`, `CUSTNAME` as `8(3)`, `CUSTBAL` as `28(3)`.
- The same DSECT serves another record by `DROP 3`, `LA 3,CUSTREC2`, `USING CUSTD,3`. The names do not change and now read the second record.

## Four Uses in the Repo

| Use | Program | Register | Real storage |
|---|---|---|---|
| Over constants | DS01DSCT | R3 | `CUSTREC`, `CUSTREC2` (`DC`, 33 bytes each) |
| Over a read buffer | DS02DSCT (`PARTD`) | R3 | `INAREA`, filled by `GET` |
| Over a parameter block | DS02DSCT (`PARMD`) | R1 | `PARMAREA`, built by `BUILDTOT` |
| Over an IBM control block | QSAMPROC, BR09MTCH (`IHADCB`) | R2 | A DCB |

The read buffer is the normal use. DS01DSCT uses `DC` data only to keep the first lesson simple.

## Two DSECTs at Once

`BUILDTOT` in DS02DSCT has two mappings active together:

```
         LA    3,INAREA
         USING PARTD,3                 * R3 maps the record
         LA    1,PARMAREA
         USING PARMD,1                 * R1 maps the parameter block
         MVC   PARMAMT,PARTAMT         * Target via R1, source via R3
         DROP  3
         DROP  1
         BAL   9,ADDAMT
```

- Each `USING` names its own register, so the assembler picks the right base for each operand.
- `DROP` does not change a register. R1 still holds the block address at the `BAL`.
- `ADDAMT` knows only `PARMD`. It issues its own `USING PARMD,1`, adds `PARMAMT`, and issues `DROP 1`.

## The IBM Map: DCBD

`DCBD DSORG=PS,DEVD=DA` generates the `IHADCB` DSECT. BR09MTCH uses it in one routine for all six DCBs:

```
OPENCHK  DS    0H                      * R2 = address of a DCB
         USING IHADCB,2
         TM    DCBOFLGS,DCBOFOPN       * Is the open bit on?
         DROP  2
         BR    10                      * CC is the answer
```

- The same names read whichever DCB R2 points at.
- The caller does `LA 2,dcb`, `BAL 10,OPENCHK`, then `BNO OPNERRn`. `DROP` and `BR` do not change the condition code, so the `TM` result is still valid at the `BNO`.

## Placement

- A `DSECT` statement ends the current control section, so no real storage can be defined after it.
- Order at the end of a source: code, data, DCBs, `LTORG`, the DSECTs, `END`. DS02DSCT has `PARTD`, then `PARMD`, then `END`. BR09MTCH and QSAMPROC have `DCBD` as the last statement before `END`.
- `LTORG` comes before the DSECTs so the literals stay in the CSECT.

## Rules

- The names are only displacements. If the register holds a wrong address, the names read other storage and no error is reported.
- Nothing checks that the real record is as long as the map. `CUSTD` is 8 + 20 + 5 = 33 bytes and each `DC` record is 33 bytes. The DS01DSCT comments say 30; they are wrong and the code is correct.
- A name with no length coded takes the length from its `DS`: `UNPK ZONE,CUSTBAL` uses 5 from `PL5`.
- A map and the buffer it describes must agree in another program too. `PARTD` in DS02DSCT and `OUTREC` in DS02BILD must have the amount at displacement 30, and nothing checks it.
- Drop a register before reusing it for another map, so the intent is visible in the source.

## Common Failures

| Symptom | Cause | Fix |
|---|---|---|
| Fields show unrelated data | Register not loaded before the first name, or loaded with a wrong address | `LA` before use; check the address |
| Fields show the previous record | `USING` still active with the old register contents | Reload the register for each record |
| ASMA error on a name | `USING` missing, dropped, or for another register | Check the `USING` and `DROP` pairs |
| Storage defined after a DSECT is not in the program | `DSECT` ends the CSECT | Put every DSECT after `LTORG`, last before `END` |
| Fields off by a few bytes | Map length differs from the real record | Add the field lengths and compare with `LRECL` |
| `BNO` after `OPENCHK` gives the wrong answer | An instruction between `TM` and `BNO` changed the CC | Keep them adjacent |
